# wadachi

[![CI](https://github.com/m96-chan/wadachi/actions/workflows/ci.yml/badge.svg)](https://github.com/m96-chan/wadachi/actions/workflows/ci.yml)

[English](README.md) | 日本語

> 二人の予定と思い出を、いつものカレンダーとアルバムのまま共有するカップルアプリ。

> **ステータス: 構想段階。** アプリは起動するだけの雛形です。このドキュメントは設計の叩き台です。

---

## 1. なぜ作るのか

Between にはカレンダーがありますが、**Google カレンダーや TimeTree の予定を取り込む機能がありません**。普段の予定は別のカレンダーに入っているため、Between には手で入力し直すしかなく、結局使わなくなります。

wadachi は**取り込みを中心に据えます**。普段使っているカレンダーとアルバムを読み込み、二人の間で重ねて見られるようにします。

## 2. 設計方針

| 方針 | 内容 |
| --- | --- |
| **サーバーレス** | 自前のサーバーは持ちません。データは各自の端末と、各自の Google アカウントに置きます |
| **既存サービスが正本** | 予定の正本は Google カレンダー、写真の正本は各自のフォトライブラリ／クラウドです。wadachi はそれをつなぐだけです |
| **対面でリンク** | パートナーとのリンクは、二人が画面を見せ合ってコードを交換して行います。アカウント登録や招待メールは使いません |
| **最小限の公開** | 相手に見せる範囲（予定の詳細か「予定あり」だけか）は、自分で選べます |

## 3. スコープ

### 強化する機能

1. **Google カレンダー連携**
2. **TimeTree 連携**
3. **アルバム連携**

### 優先度低

- **メッセンジャー**: P2P でサーバーレスでも作れる見込みですが、他のアプリで足りているため後回しにします。

### 対象と配布

- iPhone（iOS）と Android
- App Store / Google Play に個人で公開します

## 4. 連携の仕組み（案）

### Google カレンダー

自前のサーバーを持たずに共有するため、Google カレンダーの共有機能を同期の土台にします。

- リンク時に、どちらかの Google アカウントに **「二人のカレンダー」** を作成し、相手のアカウントに編集権限を付与します（Calendar API の ACL）。
- 各自の個人カレンダーは、相手に **空き時間のみ（freeBusyReader）** または **詳細** で共有します。どちらにするかは本人が選べます。
- アプリは両方を重ねて表示します。予定の書き込み先は「二人のカレンダー」です。
- 同期は Google が行うので、wadachi 側にサーバーはいりません。

### TimeTree

TimeTree は外部からの読み出し手段が限られています（2026 年 9 月時点の調査）。

| 手段 | 状況 |
| --- | --- |
| 公開 API（TimeTree Connect） | 2023 年 12 月 22 日に終了 |
| ICS などの一括エクスポート | 公式機能なし |
| OS カレンダー → TimeTree の表示 | あり（「すべてのカレンダー」に自動で表示される） |
| OS カレンダー → TimeTree への取り込み | あり（「OSカレンダーの予定をコピー」。1 回限りで、その後の変更は反映されない） |
| TimeTree → OS カレンダーへのコピー | あり（予定ごとの手動コピー。コピー先の OS カレンダーを設定で有効にする必要がある） |
| 非公式ツール（TimeTree-Exporter など） | Web 版を解析してメールアドレスとパスワードでログインする方式。予告なく動かなくなる可能性があり、ストア配布のアプリでは採用しない |

そのため、次の方針にします。

- **wadachi → TimeTree**: 「二人のカレンダー」を Google に置けば、TimeTree の「すべてのカレンダー」にも表示されます。
- **TimeTree → wadachi（取り込み）**: 次の 2 つを用意します。
  1. **OS カレンダー経由**: TimeTree の予定コピーで「二人のカレンダー」（端末に追加した Google カレンダー）を直接コピー先に選べるようにし、その手順を案内します。wadachi は EventKit / CalendarContract から読み込みます。
  2. **スクリーンショット取り込み**: TimeTree のリスト表示のスクリーンショットを端末内で文字認識し（Vision / ML Kit）、予定の候補を作ります。ユーザーが確認してから登録します。サーバーは使いません。

### アルバム

2025 年の Google Photos Library API の変更で、他のアプリが作ったアルバムや共有アルバムを API から扱うことはできなくなりました。iCloud 共有アルバムも PhotoKit から作成できません。iPhone と Android の組み合わせにも対応するため、候補は次の通りです。

| 案 | 仕組み | 長所 | 短所 |
| --- | --- | --- | --- |
| A. Google ドライブ共有フォルダ | アプリが作ったフォルダを相手と共有し、写真を置く | サーバー不要、OS をまたげる | 容量は Google ドライブを消費する |
| B. P2P 転送 + 端末保存 | 近くにいるときや同時にオンラインのときに直接送る | クラウドを使わない | 二人が同時にオンラインでないと届かない |
| C. 参照のみ | 写真は各自のライブラリに置いたまま、予定との紐付け情報だけを共有する | データが軽い | 相手の写真は見られない |

現時点では **A を基本にし、写真の選択には各 OS のピッカー（Photos Picker / Google Photos Picker API）を使う** 案が有力です。

## 5. パートナーとのリンク

1. 二人が同じ場所で wadachi を開く
2. 片方の画面に QR コード（または短いコード）を表示し、もう片方で読み取る。逆方向も同様に行う
3. 交換する内容: 端末の公開鍵、Google アカウントのメールアドレス（カレンダーとフォルダの共有に使う）、ペア ID
4. 双方の画面に同じ確認用の数字が出たらリンク完了

対面で交換するため、なりすましの心配が少なく、鍵を検証するためのサーバーもいりません。リンク解除は、どちらか一方から行えます（共有権限も取り消します）。

## 6. 機能アイデア（検討中）

まだ決定ではありません。優先度は仮です。

### カレンダー

| アイデア | 内容 | 仮優先度 |
| --- | --- | --- |
| 二人の空き日ハイライト | 二人とも予定がない日と時間帯を強調表示する | 高 |
| デートの提案と承認 | 候補日を送り、相手が承認すると「二人のカレンダー」に登録される | 高 |
| 記念日の自動生成 | 付き合った日から 100 日、1 年、誕生日などを自動で登録する | 中 |
| 公開範囲の切り替え | 予定ごとに「相手に詳細を見せる／予定ありだけ／見せない」を選ぶ | 中 |
| ホーム画面ウィジェット | 「次に会う日まであと◯日」、今日の二人の予定 | 中 |
| 移動時間の考慮 | 予定の場所から、会える時刻を逆算する | 低 |

| アイデア | 内容 | 仮優先度 |

| 思い出タイムライン | 予定と写真を並べて、二人の履歴として見返せるようにする | 中 |
| 「◯年前の今日」 | 過去の同じ日の予定と写真を通知する | 低 |

## 8. 開発

### 技術スタック

**Kotlin Multiplatform + Compose Multiplatform** で、ロジックと UI を共通化します。各 OS の API（EventKit / CalendarContract、Vision / ML Kit、写真ピッカー、ウィジェット）は expect/actual や各 OS のネイティブコードで扱います。

| ディレクトリ | 内容 |
| --- | --- |
| `shared/` | 共通コード（UI とロジック）。`commonMain` / `androidMain` / `iosMain` |
| `androidApp/` | Android アプリ本体 |
| `iosApp/` | iOS アプリ本体。Xcode プロジェクトは XcodeGen で `project.yml` から生成します |

### 必要なもの

- JDK 21（Android Studio 同梱のものでも可）
- Android SDK Platform 37
- Xcode 26 と XcodeGen（iOS のみ）

### ビルド

```sh
# Android
./gradlew :androidApp:assembleDebug

# テスト
./gradlew :shared:allTests

# iOS（Xcode プロジェクトを生成してから Xcode で開く）
cd iosApp && xcodegen generate && open iosApp.xcodeproj
```

Xcode のビルド時に、Kotlin のフレームワークは Gradle でビルドされます。`JAVA_HOME` が未設定の場合は Android Studio 同梱の JDK を使います。

### CI

`main` への push と PR で、GitHub Actions が次を実行します。

- **Android**: テスト、lint、デバッグ APK のビルド（APK は Actions の成果物として 7 日間保存）
- **iOS**: iOS シミュレーターでのテスト、アプリのビルド

### リリース

`v1.2.3` の形式のタグを push すると、署名済みの APK を添付した GitHub Release が作られます。ソースコード（zip / tar.gz）は GitHub が Release に自動で添付します。

```sh
git tag v0.1.0
git push origin v0.1.0
```

バージョン名はタグから取ります。versionCode は `メジャー × 10000 + マイナー × 100 + パッチ` です。

#### 初回だけ必要な準備（署名鍵）

APK の署名鍵を作り、リポジトリの Secrets に登録します。**この鍵を失うと、同じアプリとして更新を配布できなくなります。** `.jks` ファイルとパスワードは、リポジトリの外に必ずバックアップしてください。

```sh
keytool -genkeypair -v -keystore wadachi-release.jks \
  -alias wadachi -keyalg RSA -keysize 4096 -validity 10000

gh secret set ANDROID_KEYSTORE_BASE64 < <(base64 -i wadachi-release.jks)
gh secret set ANDROID_KEYSTORE_PASSWORD
gh secret set ANDROID_KEY_ALIAS --body wadachi
gh secret set ANDROID_KEY_PASSWORD
```
